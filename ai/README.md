# AI usage

## Tools and models

- **Claude Code** (CLI, model Claude Opus 5.5) working directly in the repo: reading files, running the app and the Playwright suite.

## What I delegated to AI

- Reading `SPEC.md`, `USER_REPORTS.md`, `docs/API.md` and the app source, and producing a first list of suspected bugs with likely root causes.
- Analyzing the seed data to find concrete repro cases (e.g. which price × quantity combos hit the rounding bug: 3 × $8.35; which seed order sits near midnight in Argentina time: order #2).
- Drafting the Playwright tests (UI and API), `BUGS.md` and `ANALYSIS.md`.

## What I verified and how

- **Every bug has a test that fails today** for the reason described. We ran `npm test` and read each failure's actual value (e.g. `percent: 0` for `flock10`, `$25.04` vs `$25.05`, `10/15/2026` vs `10/14/2026`, an approved `$129` payment after the "payment failed" message). The existing example tests still pass.
- Reproduced the user reports manually in the browser: Report 1 i added the Ergonomic Chair and went to Checkout using card 4242424242424242 and i got the "We couldnt process your payment. Please try again" message.

Report 2: Regarding the lowercase coupon i tried with flock10 to double check and the discount says its applied but applies 0%, using the uppercase coupon works.

Report 3: i added the Desk Lamp to the cart manually from the Products view and refresh the site, the cart was empty, i tried it too refreshing directly from the cart and the result was the same. Adding it from the details page works and i was able to refresh.

- Checked that the tests follow the challenge rules: bug ID in the name, `resetData` in `beforeEach`, `data-testid` locators, no access to `app/`, no `skip`/`fixme`/`fail`.
- Made sure the tests would **pass on a fixed version** and not depend on each other's bugs (e.g. the BUG-09 catalog test navigates in-app so BUG-08's lost cart doesn't hide it, and the BUG-02 "not charged" test accepts either a success screen or an error with no charge).

## What I discarded or corrected from the output, and why

- The first draft of the BUG-09 catalog test reloaded the page before checking the cart. Because of BUG-08 the cart was then empty, so the test **passed vacuously**. It was rewritten to navigate without reloading.
- BUG-12 (accented names rejected) is kept but explicitly marked as an **assumption**, because the spec defines no validation rules.
